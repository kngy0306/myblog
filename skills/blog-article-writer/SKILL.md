# Blog Article Writer

この skill は、このリポジトリ向けにブログ記事を1本作成するときに使う。

## Workflow

1. ユーザーに何を書きたいかを質問する。
   - 記事テーマ、想定読者、読後に持ち帰ってほしいこと、文体の希望が未指定なら確認する。
   - 記事の意図が構成を選べる程度に明確になるまで、執筆を始めない。

2. 参考リソースがあるかを質問する。
   - 参考にしたい記事、Pull Request、Issue、ドキュメント、コードパス、リリースノート、URL があるか確認する。
   - PR や Issue がある場合は、関連する議論、差分、リンクされた Issue、最終実装を確認してから書く。
   - 参考リソースがない場合は、リポジトリ内の文脈と、必要に応じて信頼できる Web 情報を使うことを伝える。

3. 執筆前に事実関係を確認する。
   - 公式ドキュメント、仕様、ソースリポジトリ、リリースノート、PR、Issue、メンテナーによる情報などの一次情報を優先する。
   - 二次情報は文脈理解の補助として使い、一次情報がある場合は権威ある根拠として扱わない。
   - Web を使う場合は、重要な主張を信頼できる情報源で確認し、作業メモまたは最終回答に出典 URL を示す。
   - 時間に依存する話題では、公開日、バージョン番号、現在の挙動を確認してから書く。
   - ベンチマーク値、API の挙動、互換性、因果関係を推測で書かない。

4. AIO と読者の読みやすさを優先して構成する。
   - 結論や主な学びを記事の前半に置く。
   - 具体的な主題が伝わるタイトルにする。
   - 見出しは「この節で何が分かるか」が伝わる表現にする。
   - 読みやすくなる場合は、短い段落、具体例、箇条書きを使う。
   - 読者にとってなじみが薄い用語は、深く使う前に説明する。
   - 背景、課題、方針、実装、トレードオフ、まとめは、読者の理解に必要なものだけ入れる。
   - AI が正確に要約しやすいように、主張を明確にし、用語を一貫させ、暗黙の前提を減らす。

5. MDX 記事を書く。
   - `src/content/blog/` 配下に `YYYY-MM-DD-short-slug/` 形式のディレクトリを作る。
   - その中に `index.mdx` を作る。
   - frontmatter は次の形式にする。

```mdx
---
title: "記事タイトル"
date: 2026-07-04
tags: ["tag"]
description: "記事の要約"
---
```

   - `date` にはユーザー指定日または現在日を使う。
   - slug は小文字、ASCII、ハイフン区切りにする。
   - ユーザーが指定しない限り、日本語で書く。
   - MDX として有効な構文にし、JSX と衝突しやすい文字は必要に応じてエスケープする。

## 執筆基準

- 流暢さより正確さを優先する。
- 事実、解釈、意見を分ける。
- 詳細に入る前に、その話題がなぜ重要かを説明する。
- 汎用的な導入、薄いまとめ、根拠のない主張を削る。
- 依頼にない機能、例、抽象化を追加しない。
- 近い既存記事に明確な書き方がある場合は、その文体に合わせる。
- 依頼内容が曖昧な場合は、方向性を決める前に質問する。
